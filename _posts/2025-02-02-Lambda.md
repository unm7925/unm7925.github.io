## __람다식의 개요__

### __람다식의 정의__

먼저, 내가 알아본 바에 의하면 모두다 정의는 이것이다. 라고 따로 써두지않고,<br>
람다식은 `익명함수`를 지칭한다 혹은 기능적인 부분을 이야기 하는 경우가 많이보인다.<br>

람다식은 익명함수를 지칭하기에, 익명함수의 정의를 읊어보자면 <br>

컴퓨터 프로그래밍에서 식별자에 `바인딩`되지 않은 함수 정의이다. <br>

라고 이야기하는데 이것을 보고 한번 생각해보자. <br>

간단하게 이야기하자면 함수를 직접 호출할 수 있는 이름이 없는 함수라고 보면 될 거같아. <br>

와닿지는 않지만 그래도 이해는 할 수 있는 정도인 것 같다.<br>

C#에서 람다식은 `delegate`(델리게이트)의 축약형 표현으로, `=>` 연산자를 사용해 <br>

이때, 람다식 자체가 `익명 함수`이기에, 반드시 변수나 다른 구조 (델리게이트, Func, Action 등)에 저장하여 사용해야 된다.

그렇다면 이 람다식을 알았으니 특징에 관하여 더 알아보도록 하자.

### __람다식의 특징__

대체 어디서 사용하는 걸까?? 바로 그건 방금 살펴본 정의에서 알 수 있듯이<br>

이 아이는 그냥 `일회용 컵`이다. 사용하면 바로 버려버린다. <br>

간혹 일회용품도 씻어서 다시 사용하는 알뜰살뜰 생활하는 분이 있지만 <br>

이 컴퓨터는 바로 버려버린다. 나의 자취하던 때가 떠오르게 말이다 <br>

그래서 보통, 재사용하지 않는 경우에 많이 사용한다. <br>

일상생활도 똑같다. <br>

집에서 커피를 타서 마신다면 머그컵을 이용하고 <br>
밖에서 커피를 사서 마신다면 일회용컵을 받는 것 <br>

우리가 코드를 짤 때도 똑같을 것이다. 엄청 자주 사용하는 코드가 있고,<br>
필요하지만 딱 한 두 번만 사용하는 코드가 있을 것 이다. <br>
이에 맞춰 사용하면 될 것이라고 본다.<br>

그리고, 람다식은 느긋한 계산법으로 분류되는데 <br>

느긋한 계산법은 필요할 때만 실행되는 특성을 일컫는다.<br>

즉, 람다식은 계산을 미루고 있다가 실제로 호출될 때만 평가된다. <br>

이로인해, 리소스를 아낄 수 있다. <br>

슬슬 기능적인 이야기가 튀어나오니 기능적인 부분으로 바로 넘어가보도록 하자.

___

### __람다식의 기능적 분류__

큰 틀로는 식 람다, 문 람다로 분류된다. 이게 무엇이냐?

1. 식 람다(Expression Lambda)
  - 단일 표현식만 포함 `{}` 사용 X
  - 자동으로 반환 값이 설정
  - 코드가 짧고 간결함
  - `return` 사용할 필요성 X
  ```
  Func<int, int> square = x => x * x; // 한 줄 표현
  Console.WriteLine(square(4)); // 출력: 16
  ```

2. 문 람다(Statement Lambda)
   - 여러 문장을 포함하며 `{}` 사용
   - `return` 명시적 사용
   - 여러 줄로 구성될 수 있음
  ```
  Func<int, int, int> add = (a, b) =>
  {
     Console.WriteLine($"Adding {a} and {b}");
     return a + b;
  };
  Console.WriteLine(add(3, 4)); // 출력: 7
  ```

조금 더 세부적으로 활용되는 방식도 한번 간단하게 알아보도록 하자.

- 인자를 받아 값을 반환하는 함수
   ```
  Func<int, int> doubleNum = x => x * 2;
  Console.WriteLine(doubleNum(4)); // 출력: 8
  ```


 - 여러 개의 인자를 받는 경우
  ```
  Func<int, int, int> multiply = (x, y) => x * y;
  Console.WriteLine(multiply(3, 5)); // 출력: 15
  ```



- 반환 값이 없는 경우 (Action)
  ```
  Action<string> greet = name => Console.WriteLine($"Hello, {name}!");
  greet("Alice"); // 출력: Hello, Alice!
  ```


- 여러 문장을 포함하는 경우 (중괄호)
  ```
  Func<int, int, int> addAndLog = (a, b) => 
  {
    Console.WriteLine($"Adding {a} and {b}");
    return a + b;
  };
  Console.WriteLine(addAndLog(3, 4)); // 출력: 7
  ```

이렇게 좀 큰 틀로 나눠져 다양한 방식으로 사용되고 있다.<br>

그렇다면 이 많은 방식 중 생각하고, 유의해야 될 것에 대해 알아보자.

### __유의사항__

우선, 위의 코드들을 살펴보면 알겠지만 매우 간결한 만큼 가독성이 떨어진다. <br>
우리 실생활과 같다. 말을 줄여쓰면 편하지만 알아듣기 점점 힘들어지지 않는가? <br>
세대차이라고하면 할 말이 없다 ㅋㅋㅜ <br>

또한 디버깅이 어려워질 수 있다. 콜스택 추적도 어려워질 것 이다. <br>

그리고 외부 변수의 캡쳐 시점에 대해 명확하게 이해하지 못하면 멀티스레드나 비동기 프로그래밍 때 잘못된 값이 사용(누수)될 수 있을 것이다. <br>

또한, LINQ에서 Expression<Func<T, bool>> 타입으로 사용할 때는 표현식이 필요하고, `{}` 를 사용하면 안된다. <br>

한마디로 너무 자주 사용하지말고, 상황 봐가면서 써라 라는 말이다. <br>
